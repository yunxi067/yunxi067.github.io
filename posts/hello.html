2026-05-27 · GitHub Pages

博客上线记录

这个博客从一个空的 GitHub Pages 仓库开始，采用纯静态页面发布。目标不是一开始就追求复杂系统，而是先建立一个稳定、可持续更新的技术输出阵地。

为什么选择纯静态

对个人技术博客来说，第一阶段最重要的是写作和发布闭环，而不是后台、评论、主题市场或复杂构建链。纯 HTML、CSS 和 GitHub Pages 足够稳定，也足够透明。

这种方式的好处是维护成本极低：没有数据库，没有服务端运行时，没有依赖升级压力。每次发布就是一次文件变更和一次 Pages 部署，出问题也容易定位。

当前站点结构

文件 作用
index.html 首页和文章入口，负责呈现博客定位、精选内容和文章库。
styles.css 全站视觉系统，包括首页、文章页、图表、表格和响应式布局。
posts/ 每篇文章一个独立 HTML 文件，方便静态托管和长期维护。
assets/ 站点图标和文章配图。

后续演进

如果文章数量增长到几十篇，可以再引入 Astro、VitePress 或静态站点生成器，把文章迁移成 Markdown。但在内容还不多的时候，先把每篇文章写扎实，比搭更复杂的框架更有价值。

本文要点

先建立稳定发布闭环，再考虑复杂化。个人博客第一阶段最重要的是持续输出。
